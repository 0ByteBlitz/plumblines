# npx CLI: init and gates in pure Node

## Metadata

Date: 2026-05-31
Agent: Claude (Opus 4.8)
Branch: main
Domain: tooling / distribution

## Goal

Add the npx distribution path that was scoped but not built in the
easy-integration work ([[2026-05-31-easy-integration]]): let users adopt
Plumblines with `npx plumblines init` — no clone, no bash — and run the gates
with `npx plumblines check`.

## Summary

A dependency-free Node CLI under `cli/`, mirroring the shell tooling:

- `init.js` reimplements the scaffolder. It reads bundled assets from the
  installed package (so it works via npx with nothing checked out), writes the
  `.agent_files` tree, `.plumblines`, and `.gitignore`, stamps the current
  commit into state files, and drops the shell `scripts/` into the target so
  bash/CI wiring still works.
- `lib.js` is a Node port of `plumblines-lib.sh` (frontmatter parser, trust
  ranks, config loader, record discovery) with forward-slash paths to match the
  shell output.
- `checks.js` ports both gates; `index.js` dispatches `init`, `check`,
  `check-completeness`, `check-staleness`.
- `package.json` exposes the `plumblines` bin and a `files` whitelist that
  publishes `cli/templates/skills/scripts/docs` but not `.agent_files/`.
- `.gitattributes` now forces `*.js`/`*.json` to LF so the published bin's
  shebang works on Linux/macOS.

`cli/` and `test/` were added to this repo's `src_globs` so the CLI source is
gated like the rest of the framework.

## Behaviour Before

Setup required a clone plus bash or PowerShell; there was no registry-installable
entry point and no Node implementation of the gates.

## Behaviour After

`npx plumblines init` (or `npx github:0ByteBlitz/plumblines init`) scaffolds a
working tree with zero bash, and `npx plumblines check` runs the gates in Node.
The shell path is unchanged.

## Validation Summary

`node test/cli.test.js` — 15 assertions pass, including byte-for-byte parity
between the Node and shell gates across all three failure modes (uncovered
commit, trust escalation, staleness). Manually verified `npx`-style `init`
scaffolds a clean, gate-passing tree, and `npm pack --dry-run` ships the
correct file set while excluding `.agent_files/`. Node confirmed all CLI files
are pure LF.

## Risks

- The Node and shell gates are two implementations of one contract. They are
  byte-identical today and guarded by `test/cli.test.js`, but a change to one
  parser must be mirrored in the other or the test will fail.
- Publishing to npm is a manual maintainer step; until then only the `github:`
  form works.

## Follow-ups

- `npm publish` so `npx plumblines` resolves without the `github:` prefix.
